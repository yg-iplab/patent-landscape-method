# 03 集計と図

名寄せした母集団を、年・技術分類・出願人・共同出願人で集計し、図にします。
そのあと、数字を「事実」「読み」「仮説」に分けて書きます。

- 入力：`02` で作った `results.tsv`（または出力した CSV）、`name_map.csv`
- 出力：`charts/aggregate.md`（集計結果）、CSV、SVG の図、事業との対応表、文章（事実・読み・仮説）
- 使う道具：`scripts/ipl_aggregate.py`（標準ライブラリだけで動きます）

---

## 1. 集計する

```bash
python3 scripts/ipl_aggregate.py \
  --input ./work/{会社名}/jplatpat/results.tsv \
  --name-map ./work/{会社名}/name_map.csv \
  --applicants-csv ./work/{会社名}/jplatpat/{国内文献のCSV}.csv \
  --company "{会社名}" --as-of YYYY-MM-DD \
  --out ./work/{会社名}/charts
```

主なオプション：

| オプション | 意味 |
|---|---|
| `--date 出願日`／`公知日` | 年を切る日付の種類（既定は出願日） |
| `--fi-level subclass`／`maingroup`／`full` | FI を何桁で数えるか（既定はメイングループ） |
| `--fi-mode first`／`all` | `first`＝筆頭の FI だけ数える（既定。重複なし）／`all`＝付いた FI を全部数える |
| `--split-year 年` | 前半・後半を分ける年（既定は期間の中間） |
| `--as-of` | 取得日。未公開分の印に使う |
| `--col 出願日=出願年月日` | 列名が自動で見つからないときの指定 |

出るもの（`charts/`）：

| ファイル | 中身 |
|---|---|
| `aggregate.md` | 年ごとの件数（直近2年は「未公開分あり」の印）／FI の上位と前半・後半のシェア、割合が伸びた分類、後半に初めて現れた分類／名寄せ後の出願人と、名寄せ表に無かった表記／共同出願人 |
| `yearly.csv`・`yearly.svg` | 年ごとの件数 |
| `fi_share.csv`・`fi_share.svg` | FI のシェアの変化 |
| `applicants.csv` | 名寄せ後の出願人 |
| `coapplicants.csv` | 共同出願人の件数 |

- 件数の単位は「出願」です（出願番号で重複を除きます）
- 母集団が数百件規模なら、FI は `subclass` かメイングループで見るのが現実的です。件数が少ない分類のシェアは大きく揺れるので、数件の差を傾向と読みません
- `aggregate.md` の「名寄せ表に無かった表記」を見て、名寄せ表に足し、もう一度集計します。表記が出尽くすまで繰り返します

## 2. 図の書き方

どの図にも、次の4点を図の注記か直下に書きます。

1. 件数の単位（出願／ファミリー）
2. 日付の種類（出願日／公開日）
3. 取得方法と取得日（例：J-PlatPat・論理式・出力日）
4. 途中の数（例：検索結果 N 件 → 重複除去 M 件 → 期間内 K 件）

その他：

- 直近2年は出願から公開までの遅れで件数が少なく見えます。伸び・減りの判断に使わず、図でも印を付けます
- 1枚の図に載せる分類は、上位5〜10行にします。表紙用の図は5行程度に絞ります
- 図は SVG で出します。そのまま文書に埋め込めます（`scripts/render_report.py`）

## 3. 事業と技術分類を対応づける

`ipl_aggregate.py` は分類までを数えます。**事業セグメントとの対応は、人が表にします。**

| セグメント | 売上・利益・研究開発費（有価証券報告書 {年度}・頁） | 対応させた FI | 出願の推移（10年） | 対応づけの根拠 |
|---|---|---|---|---|

- 根拠を1行ずつ書きます（「この FI は、このセグメントの主製品の分類にあたる」など）
- 単一セグメントの会社は、セグメントの代わりに主な事業の領域や製品群で分けます
- 並べる事実は3つに分けます：伸びている分類／新しく現れた分類／減っている分類。どれも出願の数と割合を示すだけで、理由は書きません

## 4. 共同出願人を読む

`coapplicants.csv` と `aggregate.md` の共同出願人を、相手の種類で分けます。

- 大学・研究機関／顧客（事業会社）／合弁・子会社／その他
- 種類の自動判定は名前の語（大学・研究所など）による目安です。「研究所」を名乗る株式会社が大学・研究機関に入るなど、外れます。人が確かめます
- 相手が個人の場合は、人数まで書き、名前は出しません
- 共同出願の割合と、相手の種類の推移（3年ごと）を見ると、連携の形の変化が読めます

## 5. 質の近似（任意）

件数とは別に、出願の「質」を近似で見る方法があります。**近似であることを必ず書きます。**

- ファミリーの国数：どの国・地域に出しているか
- 前方引用数：後の特許から引用された回数
- 取得方法：Google Patents の画面検索結果の CSV（上位1,000件まで）。列（被引用数・ファミリー）は初回に実物で確認します。足りなければ、Google の BigQuery の公開データセット（`patents-public-data`）を使う手があります。BigQuery は `SELECT *` を使わず、必要な列だけを選び、実行前に処理量（dry run）を確かめます

書いてよいこと：「無料データでの近似です。有償データベースの指標とは計算方法が違います」
書かないこと：有償データベースの指標を再現した、同じ結果だ、という書き方

統合報告書に有償データベースの指標の図がある会社は、近似と並べて、**合う所・ずれる所と、その理由**を書きます。理由の多くは、指標そのものが別物であること、母集団の違い（出願人の範囲、期間、分類）です。

## 6. 事実・読み・仮説に分けて書く

数字が出たら、次の3段で書きます。段ごとにラベルを付けます。

| ラベル | 内容 | 書き方 |
|---|---|---|
| 事実 | 数字と出典（検索ログの行、有価証券報告書の頁、URL、取得日） | 「出願が◯年から増えています（出願日・出願単位）」 |
| 読み | 事実から外から見て考えられること | 「外から見える範囲では〜と読めます」 |
| 仮説 | 読みを踏まえた、確かめたいこと | 「〜ではないかと考えました。実際はどうか確かめたい」 |

- 仮説は3つ程度にします。仮説ごとに、根拠にした事実、別の読み方、確かめ方を添えます
- 別の読み方を必ず1つ書きます（例：件数の増加は、承継で受け継いだ出願が混ざったためかもしれない）
- 結論を断定にしないための書き方は `05_限界と注意.md` にまとめています
