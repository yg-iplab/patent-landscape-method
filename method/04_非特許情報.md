# 04 非特許情報

特許の数字だけでは、「なぜその方向か」「社内でどんな言葉が使われているか」が分かりません。
有価証券報告書・統合報告書・論文・雑誌を重ねて、出願の動きに文脈を与えます。

- 入力：`design.md`、`name_map.csv`
- 出力：事業の数字の抜き出し（`data/edinet_extract.md` など）、文献の候補リスト（`reading/candidates.md`）、読んだ要点（`reading/notes.md`）
- 使う道具：`scripts/edinet_fetch.py`、`scripts/pdf_text.swift`、`scripts/biblio_search.py`

出典は、数字ごとに「資料名・年度・頁（または URL）・確認日」を付けます。

---

## 1. 有価証券報告書（EDINET）

金融庁の EDINET から、有価証券報告書を取ります。

- API キーは無料で、利用者本人が登録します（https://api.edinet-fsa.go.jp/WEEE0090.aspx）
- キーの置き場：環境変数 `EDINET_API_KEY`、またはカレントの `./.env` に `EDINET_API_KEY=…`。`.env` は git に入れません。画面・ログ・文書にキーを出しません
- 書類の種類：有価証券報告書は `docTypeCode` が `120`、訂正は `130`。3月決算の会社は6月下旬に出ます
- 取得の種類：`type=1` XBRL一式、`type=2` PDF、`type=5` CSV（XBRL を表にしたもの）

```bash
python3 scripts/edinet_fetch.py find --name "{会社名}" --from YYYY-MM-DD --to YYYY-MM-DD
python3 scripts/edinet_fetch.py get --doc-id {docID} --type 2 --out ./work/{会社名}/data/raw
python3 scripts/edinet_fetch.py get --doc-id {docID} --type 5 --out ./work/{会社名}/data/raw
python3 scripts/edinet_fetch.py extract --csv-dir ./work/{会社名}/data/raw/{docID}_csv \
    --out ./work/{会社名}/data/edinet_extract.md
```

- `find` は1日ずつ問い合わせるので、期間は2か月以内にします。`--wait`（間隔）と `--env` は、サブコマンドの前に置きます
- 誤ったキーでも HTTP 200 が返り、本文の `StatusCode` に 401 などが入ります。スクリプトは本文の値を見ています
- `extract` が出すのは、セグメント・研究開発費・売上・利益などの「候補の行」です。**表に使う数字は、PDF の該当頁で必ず確かめます**
- 読む節：「事業の内容」「関係会社の状況」（名寄せの根拠）「セグメント情報」「研究開発活動」
- API の仕様は更新されます。初回の実行で、認証や応答の形を確かめてください

## 2. PDF から文字を取り出す

統合報告書や有価証券報告書の PDF は、`pdf_text.swift`（macOS 標準の PDFKit を使用）で文字にできます。

```bash
swift scripts/pdf_text.swift 入力.pdf > 出力.txt
```

- 文字が画像になっている PDF（一部の統合報告書）は取り出せません。画面で読むか、該当の頁を画像にして目で読みます
- 公的機関のサイトの PDF が、ブラウザからは取得できないことがあります。その場合、頁の照合ができていない出典は「部分照合」「未照合」と書き、頁だけを記します

## 3. 統合報告書・中期経営計画・決算説明資料

会社のサイト（IR ページ）から、PDF を読みます。

- 将来像（トップメッセージ、重点領域、数値目標）→ `01` の問いの材料
- 知財のページ（出願件数の推移、使っている指標、取り組みの紹介）→ 開示の有無と中身を事実として記録する
- 有償データベースの指標の図がある場合は、`03` §5 で近似と照らす

## 4. 論文・学会発表・雑誌（候補リスト）

```bash
python3 scripts/biblio_search.py --company "{会社名}" --alias "{略称}" \
    --out ./work/{会社名}/reading/candidates.md
```

- 国立国会図書館サーチ（NDLサーチ）の OpenSearch API で書籍・雑誌（号）を、J-STAGE WebAPI で論文・学会発表を検索し、表にします。J-STAGE は所属（`affil`）で会社に絞れます
- NDLサーチ：個人の、収益を得ない利用は申請不要ですが、API を使っていることを明記します（出力の先頭に書かれます）。継続して使うなら、公式の案内に沿って連絡先を知らせます。同時に何本も投げず、間隔を空けます
- J-STAGE：キーは不要です（2026年10月時点で確認）。所属欄が空の記事は拾えません
- 通信が混み合うと、429 やタイムアウトが返ることがあります。その場合は間隔を伸ばして再実行します
- CiNii Research は、画面か API で別に検索します
- 結果は「候補」です。優先度を本文を見てつけます：
  - A：その会社の知財・研究・経営の人が書いた寄稿や発表、経営者のインタビュー（直近5年）
  - B：業界誌・経済誌の特集、技報、業界の解説書
  - C：古い（10年超）・関係が薄い

無料で読めるもの：

| 資料 | どこで | 分かること |
|---|---|---|
| 『情報の科学と技術』、情報プロフェッショナルシンポジウムの予稿 | J-STAGE | 企業の知財・情報分析の担当者の手法の発表 |
| 『パテント』誌 | 日本弁理士会のサイト | 知財実務・企業知財の論考 |
| Japio YEAR BOOK | Japio のサイト | 特許情報分析の論考・企業の事例 |
| 知財功労賞の資料 | 特許庁のサイト | 受賞企業の知財の取り組み |
| 統合報告書・技報・講演記録 | 会社のサイト | 知財ページ、研究所の技術動向 |

読んだら要点を `reading/notes.md` に書きます（出典・頁・確認日つき）。引用は短くします（1か所15語以内を目安に）。

### 書籍・雑誌の現物

最寄りの公共図書館から調べます。足りなければ、都道府県立図書館のビジネス支援の窓口、国立国会図書館の遠隔複写を使います。
所蔵のデータベースは図書館ごとに違うので、使えるものを初回に確かめます。持ち帰ったスキャンやメモは、1記事1ノートの形で要点と出典頁を残します。

## 6. 使わないもの

- 有償の特許データベース：使っていないものは、使ったと書きません
- 出所が確かめられない第三者のスクレイパーや、キーを渡す必要のある非公式のツール
- 非公開の情報（社内資料や、取引で知った事柄など）
- 個人名（発明者、担当者、論文の著者）：人数と所属の種類までにします
